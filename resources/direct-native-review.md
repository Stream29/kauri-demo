## First-pass blockers and repair conclusions

The numbered findings describe the **first-pass** defects/line numbers. Each repair note references current source and fresh evidence.

1. **Ordinary launch required a smoke-only argument.** First-pass `framework/src/nativeMain/kotlin/dev/kauri/framework/DesktopHost.kt:116-121` unconditionally constructed `Smoke(view, checkNotNull(results))`; normal startup without `--result-dir` threw before navigation.
   - **Fixed.** [Common launch:118–133](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/nativeMain/kotlin/dev/kauri/framework/DesktopHost.kt#L118) creates `Smoke` only inside `if (smoke)`. The callback is inert when smoke state is absent; the ordinary URL has no smoke query.
   - **Mac regression passed.** The standalone binary ran `--startup-check`, with neither `--smoke` nor `--result-dir`. Only data isolation, offscreen placement and automatic native close on document load differ from ordinary mode; the normal WebKit profile/URL and no-Smoke branch are used. `smoke/startup.log` records successful navigation, delegate close, return through `finally` and exit 0.
2. **Windows internal loader had the wrong ABI.** First-pass `framework/src/mingwMain/kotlin/dev/kauri/framework/DesktopHost.kt:14-18,438-440` declared/called four arguments. The [pinned internal loader](https://github.com/webview/webview/blob/0.12.0/core/include/webview/webview.h#L3290-L3393) takes five: bool, runtime enum, user-data path, options and handler; it is not the public four-argument entry.
   - **Fixed.** [Host contract:7–21](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/nativeMain/kotlin/dev/kauri/framework/HostContracts.kt#L7) uses `Boolean, Int, PCWSTR, opaque IUnknown*, opaque handler*`; installed discovery forwards `true, 0, userData, null, handler`. The embedded value is named `1`, but no new embedded-runtime discovery was added.
   - **ABI checked, not guessed.** Microsoft documents [C++ bool=1 byte, wchar_t=2, long=4](https://learn.microsoft.com/en-us/cpp/cpp/data-type-ranges?view=msvc-170), [x64 enum=32 bits and pointer=64 bits](https://learn.microsoft.com/en-us/cpp/build/x64-software-conventions?view=msvc-170), and the [Windows x64 calling convention](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170). `STDMETHODCALLTYPE` uses that x64 convention here, not a four-argument public-loader ABI.
   - **Regression passed on Mac.** [HostContractsTest:29–46](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/macosArm64Test/kotlin/dev/kauri/framework/HostContractsTest.kt#L29) calls a real C function pointer and checks all five forwarded arguments, Unicode UTF-16 path, result propagation and widths. A separate Apple clang 21 Windows-x64 **compile-only** probe passed static assertions and emitted `i1 zeroext true, i32 0, ptr data, ptr null, ptr handler` (`webview2-abi.ll`). Neither test ran WebView2 on Windows; that gate remains open.
3. **Linux blocked responses as popups.** First-pass `framework/src/linuxMain/kotlin/dev/kauri/framework/DesktopHost.kt:22-27` ignored type `2`, blocking response loads. The [WebKitGTK enum contract](https://webkitgtk.org/reference/webkit2gtk/stable/enum.PolicyDecisionType.html) defines navigation `0`, new-window `1`, response `2`.
   - **Fixed.** [Policy contract:23–40](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/nativeMain/kotlin/dev/kauri/framework/HostContracts.kt#L23) names the official 0/1/2 values. GTK only reads a navigation decision as such for type 0; type 1 blocks popups, type 2 returns the default response handling.
   - **Regression passed on Mac.** The same policy function used by GTK covers allowed/foreign/missing navigation URI, origin-prefix spoofing, popup 1 and response 2 (including absent URI). Actual WebKitGTK signal/resource-loading execution is still a Linux runner gap.
4. **Linux smoke was unfinished, not merely untested.** First-pass Linux `DesktopHost.kt:133-136` left `evaluate` empty and registered no user-content message handler.
   - **Fixed.** [GTK host:71–102](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/linuxMain/kotlin/dev/kauri/framework/DesktopHost.kt#L71) decodes `WebKitJavascriptResult` via JSC, frees the returned string and handles async evaluation completion/errors. `evaluate` calls the real `webkit_web_view_evaluate_javascript`; it is no longer a no-op.
   - A smoke-only `kauriSmoke` signal is connected **before** registering the channel. Close unregisters it, disconnects saved signal IDs, destroys/unrefs widgets, then disposes the StableRef after the GTK loop unwinds. Ordinary mode registers no test message bridge. Application calls remain typed kRPC.
   - Declarations were checked against [evaluation](https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.evaluate_javascript.html), [registration order](https://webkitgtk.org/reference/webkit2gtk/stable/method.UserContentManager.register_script_message_handler.html), [message callback ABI](https://webkitgtk.org/reference/webkit2gtk/2.38.0/signal.UserContentManager.script-message-received.html), [borrowed JS value](https://webkitgtk.org/reference/webkit2gtk/stable/method.JavascriptResult.get_js_value.html), [owned UTF-8 conversion](https://webkitgtk.org/reference/jsc-glib/stable/method.Value.to_string.html) and [signal disconnect](https://docs.gtk.org/gobject/func.signal_handler_disconnect.html). Both Linux links pass; GUI delivery/evaluation/cleanup still need isolated runners.
5. **Native user-close did not end the application loop.** First-pass Windows `DesktopHost.kt:374-380,498-505` destroyed the window without posting quit; macOS had no window-close delegate. [Win32's closing sequence](https://learn.microsoft.com/en-us/windows/win32/learnwin32/closing-the-window) distinguishes window destruction from ending its message loop.
   - **Fixed in source; Mac runtime passed.** [Mac close:104–150](file:///home/stream/ACodeSpace/demo/Kauri/framework/src/macosArm64Main/kotlin/dev/kauri/framework/DesktopHost.kt#L104) uses `NSWindowDelegate.windowWillClose`, removes handlers/delegates, stops AppKit and posts a wake event. No `terminate` remains. Ordinary regression invokes `performClose`, while smoke closes programmatically; both return through common server/temporary-data cleanup. Temporary deletion failure is now checked before emitting the cleanup-success marker.
   - Windows handles `WM_DESTROY → PostQuitMessage`; smoke requests closure by posting `WM_CLOSE`. COM teardown is deferred until after `Invoke`/message dispatch unwinds, then common `finally` stops the server. GTK delete-event likewise quits the loop without destroying callback state on its own stack. Windows/Linux target close behavior remains unexecuted.

## Additional required checks

- **Ownership repaired:** borrowed environment/controller pointers are `AddRef`'d before storage; `get_CoreWebView2` supplies an owned out-parameter. Close unregisters the three saved event tokens, calls controller `Close`, then releases owned view/controller/environment references. This follows [COM retained-copy rules](https://learn.microsoft.com/en-us/windows/win32/com/rules-for-managing-reference-counts) and [WebView2 controller lifecycle](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller?view=webview2-1.0.3650.58).
- **Late completion/failure cleanup repaired:** closed environment callbacks do not start controllers; a late borrowed controller is closed without an invalid owned `Release`. Constructor errors enter the same cleanup. Callback creation failures request loop exit rather than leaving a blank window hanging. Navigation/message COM strings are freed with `CoTaskMemFree`.
- **Safe module lifetime:** callbacks never call `FreeLibrary` from `Release`. After loop/COM teardown, unload requires both an empty handler-reference set and `DllCanUnloadNow == S_OK`. Late completions are pumped in the original STA for at most five seconds; if references remain, or the export does not permit unloading, the DLL is explicitly retained until process exit. This is a safe-retention fallback, **not proof all runtime versions release every callback promptly**.
- **Resize repaired:** initial and `WM_SIZE` bounds use `GetClientRect`; smoke shows its offscreen Win32 window with `SW_SHOWNOACTIVATE`. No native navigation/dialog framework was added.
- **Title repaired:** common launch passes `DesktopApplication.title`; AppKit, Win32 and GTK use it instead of hard-coded window titles.
- **Incremental/header-only boundary preserved:** changing the GTK declaration header initially left stale cinterop bindings; both existing cinterop tasks now declare that repository header as an explicit input. No prepared SDK/archive input, new task type, root aggregate or build-logic module was added.
- **Provenance retained:** Session 1029 remains the original delegated implementation. Session 1034 also ran a bounded, no-tool agy documentation-wording review successfully; it is not a substitute for platform testing.
- **Historical evidence retained:** the old hash table remains explicitly marked first-pass in `validation.md`; original receipt/manifest copies are under `build/review/direct-native-first-pass/`.
